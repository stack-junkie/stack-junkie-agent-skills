# Domain documentation

This repository uses a single glossary. Read `GLOSSARY.md` at the repository root when it exists. Use its terms in plans, issues, and code.

Look in `docs/adr/` for architectural decisions relevant to the change. If a proposal would reverse one, link the decision and explain what changed.

Create a glossary entry when a term is settled. Record an architectural decision when the choice involved a real tradeoff, would be costly to reverse, and needs context for a future reader.
